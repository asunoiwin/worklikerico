# 中国合同审查 Skill 设计门

## PM / 方案策划结论

- 用户目标：生成一个可在日常工作中使用、默认本地处理合同、按中国现行法律提供可追溯审查意见的 Agent Skill。
- 目标用户：合同经办人、业务负责人、内部法务和最终复核律师。
- 真实意图：交付可用且可审计的 Skill，不只是合同审查提示词。
- 目的导向：结果导向；本轮完成 Skill、配置、只读文档检查器和验证。
- 反范围：不安装到全局目录；不启用远程 MCP；不自动发送文件；不执行市场脚本；不替代执业律师；不生成生产级沙箱运行时。
- 验收口径：结构完整；默认配置可校验；DOCX 检查器只读且无网络/子进程；能识别修订、批注、隐藏内容、附件引用和高风险封装；所有法律结论要求一手来源与核验日期；外发和正式稿生成必须人工确认。
- PRD 豁免：这是单一、独立、无 API/DB/UI 的 Skill 包；用本设计文件承载等比例需求、风险和验收，不创建 issue-tracker PRD。

## 双面影响声明

- 用户面影响：新增本地合同审查工作流；先锁定文件、立场和状态，再做文本/标记检查、法源核验、风险分析和受控交付。
- Admin 面影响：无管理页面；治理能力由配置文件、审批角色、事项隔离、审计日志最小化和法源白名单承担。
- DB 影响：无数据库迁移；默认禁止持久化合同正文、个人信息和事项内容。

## 设计选择

1. Skill 采用“核心流程 + 按需参考文件 + 小型只读检查器”，避免一个超长提示词。
2. DOCX 检查器直接读取 ZIP/XML，不把归档内容解压到磁盘，不运行宏、OLE、外链或嵌入文件。
3. PDF 预检只使用本地库；库不可用或文件加密时失败关闭，不回退到远端 OCR。
4. 法律检索与合同内容处理分离：可以查询抽象法律问题，但查询中不得带合同原文、主体、金额、电话或交易事实。
5. 法律强制要求、公司标准立场、谈判区间、升级红线和本次例外分层保存，禁止混称为“法律规定”。
6. 交付状态固定为：原始基线 → 内部审查 → 建议修改 → 双方确认 → 签署候选 → 已签归档；禁止跨状态覆盖。

## 验证计划

- 校验 `SKILL.md` frontmatter、名称与目录结构。
- 校验 JSON Schema 自身可解析；用无第三方依赖的内置语义校验器验证默认配置和失败配置（当前环境未安装 JSON Schema 运行库，不自动安装）。
- 构造最小 DOCX fixture，验证正文、批注、插入、删除、隐藏文本、外部关系和嵌入对象计数。
- 构造含危险 ZIP 路径的伪 DOCX，确认只报告、不解压、不写出边界外文件。
- 静态扫描网络、子进程、shell、`--no-sandbox`、凭据读取和破坏性文件操作。
- 运行单元测试、Python 编译和帮助命令。
