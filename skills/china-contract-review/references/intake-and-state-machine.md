# 事项卡与状态机

## 事项卡

| 字段 | 规则 |
|---|---|
| 事项编号 | 本地、无客户名称的标识符 |
| 活跃文件 | 绝对路径、文件名、大小、SHA-256 |
| 文件角色 | 基准版、目标版、附件、已签版或参考材料 |
| 我方立场 | 甲方、乙方、第三方或中立复核 |
| 合同类型 | 采购、销售、服务、许可、劳动等；未知要标记 |
| 适用法 | 明示条款、推定结果或待确认 |
| 争议地 | 法院/仲裁机构和地点；未知要标记 |
| 签署状态 | 草拟、谈判、待签、已签或履行中 |
| 审查目标 | 首审、复审、比较、签前核验等 |
| 接收人与密级 | 控制输出范围和外发门 |

## 文件基线

- 所有结论绑定到 SHA-256，不只绑定文件名。
- 比较任务必须冻结“基准版 → 目标版”，不得凭“最新”“甲方版”等模糊标签推断。
- 用户更正文件、立场、任务目标或版本关系时，旧结论标为已废弃，不能继续混用。
- 已签版本与草拟版本不得覆盖；同名文件也视为不同对象。

## 状态迁移

```text
source_baseline
  -> internal_review
  -> proposed_revision
  -> counterparty_confirmed
  -> signature_candidate
  -> signed_archive
```

- 状态只能前进到下一阶段；回退时创建新版本并记录原因。
- `signature_candidate` 要有全文、附件、视觉、批注/修订和签署栏核对记录。
- `signed_archive` 要重新计算哈希，确认签署页、日期、印章/签名状态和附件集合。
- 任何哈希变化都会让先前签署候选批准失效。
