# linux-guard

一套 Linux 服务器安全脚本。中招了能救火，没出事能体检。纯 bash，不装依赖，不连网，直读 `/proc`。

## 起因

国内的云服务器出安全事故，八成不是什么高深攻击，就是这么几种：Redis 或 Docker API 开在公网还没密码，被人写进 SSH 公钥直接拿了 root；SSH 弱密码被爆破，挂上挖矿木马，CPU 跑满、对外发包；然后云厂商一封号，业务全停。

这类事有个特点：出事的时候人是慌的。机器正在发包、带宽打满、SSH 都快连不上，这时候你最不想碰到的，就是一个要联网下载、要装依赖、输出还可能被木马劫持了的工具。所以这套脚本一个 `bash` 就能跑，什么都不装，什么网都不连。

## 两种用法

**机器正在出事**（发包、CPU 跑满、云厂商告警）——用 `killswitch.sh` 止血，`harden.sh` 堵入口。这俩默认会动手：杀进程、删文件。因为救火时慢一秒都可能被封号，杀错了大不了重启服务。

**平时想检查**——用 `checkup.sh` 做体检。纯只读，不碰任何配置，生产机随时能跑。给你一份整改清单，暴露面和 SSH 配置排在补丁前面（这俩才是真出事的原因，补丁反而排最后）。

两个模式默认行为是反的，这是故意的：救火默认动手，体检默认只读。拿不准算不算"出事"，就先跑体检，或者给救火脚本加 `--dry-run`，只读的永远安全。

## 上手

```bash
git clone https://github.com/asunoiwin/linux-guard.git
cd linux-guard/scripts
```

体检，纯只读：

```bash
bash checkup.sh
```

七类检查一次跑完，大概长这样：

```
━━━ 1. 对公网暴露的服务（最高优先级） ━━━
  ✗ [高危] Redis 监听 0.0.0.0:6379 且无密码 —— 国内挖矿木马头号入口
━━━ 2. SSH 安全配置 ━━━
  ✗ [高危] 允许 root 直接登录 + 密码登录 —— 正在被爆破（日志 7054 次失败）
━━━ 4. 已知木马痕迹 ━━━
  ✓ 未发现已知木马文件痕迹
```

机器已经中招：

```bash
bash killswitch.sh --dry-run    # 先看看会杀什么，不动手
bash killswitch.sh              # 确认没问题，直接处置
bash harden.sh                  # 杀完堵入口，默认只给建议不自动改
```

多台机器批量跑：

```bash
# hosts.txt 每行一个 root@ip
bash batch.sh hosts.txt                          # 批量体检
bash batch.sh hosts.txt killswitch.sh --dry-run  # 批量只读排查
```

批量脚本写死了一条规矩：只准分发只读任务。批量跑 killswitch 强制要 `--dry-run`，真杀只能逐台人工来——一次误判会同时打到一批生产机，这个险不能冒。

## 特征库

`feeds/malware.txt` 收了 26 个还在活跃的挖矿和 DDoS 家族，来源是 Talos、微软、CNCERT、奇安信、360、Fortinet、Aqua、Wiz、Cado 这些公开威胁情报。

挖矿这边有 kinsing、8220、TeamTNT、Outlaw、RedTail、perfctl、sysrv、Diicot、Migo、Skidmap、Hadooken、Koske 这些；DDoS 那边有 XorDDoS、盖茨木马、Mozi、Gafgyt、Chalubo、Tsunami、Ballista 等。匹配的时候看五样东西：进程名、可执行文件路径、恶意端口、矿池和 C2 域名、以及存在即中招的标志文件。

## 为什么敢让它默认动手杀

杀木马不难，难的是不误杀正常业务。这块是整个项目最花心思的地方。

木马最爱伪装成内核线程。真的内核线程叫 `kswapd0`，木马叫 `kswapd01`，就多一个字符；真的叫 `kauditd`，木马叫 `kaudited`，就多一个字母。所以特征库顶部写死了一份黑名单，列明哪些真实进程名绝对不许写进去，靠"路径 + 是不是真内核线程"来区分，不靠名字硬撞。像 P2Pinfect 这种故意把自己组件命名成 `bash`、`miner` 的，干脆禁止进特征库，只靠行为判据抓。

判恶意也不是单看一张黑名单。可执行文件被删了、伪装成内核线程却能读到实体文件、从 `/tmp` 里执行、命令行里带矿池域名——这些行为凑一块才定性，比静态特征可靠。端口分两类，挖矿专用端口命中就杀，`3306`、`6379`、`8080` 这种正常业务也在用的只报告不杀。

脚本全程直读 `/proc`，绕开可能已经被 rootkit 换掉的 `ps`、`ss`、`netstat`，动手前还会先评估一次这台机器的系统命令输出还能不能信。当前 SSH 会话、脚本自己的进程、真内核线程、虚拟化宿主机上的 KVM 客户机，这些都在保护名单里，一个不许杀。

特征库每次改动都会跑 `feed-selftest.sh`：拿几十个真实系统进程名去撞，一个都不能命中才算过。

## 脚本都干什么

| 脚本 | 干什么 | 默认 |
|---|---|---|
| `checkup.sh` | 体检：暴露面、SSH、账号、木马残留、持久化、权限、补丁 | 只读 |
| `killswitch.sh` | 止血：识别、挂起、取证、杀、清文件 | 动手（可 `--dry-run`） |
| `harden.sh` | 堵入口：清 SSH 公钥、账号、PAM 后门，封暴露服务 | 只给建议（`--apply` 才执行） |
| `triage.sh` | 只读采集现场，打包交人分析 | 只读 |
| `batch.sh` | 批量把只读检查推到多台机器 | 只准只读 |
| `feed-selftest.sh` | 特征库误伤测试 | 只读 |
| `update-feed.sh` | 从 ThreatFox 拉新恶意域名，过滤后出待审清单 | 只读，不自动入库 |

## 配合 Claude Code

这个仓库本身也是个 [Claude Code](https://claude.com/claude-code) skill（`SKILL.md`）。整个目录丢进 `~/.claude/skills/`，之后在对话里说"服务器被入侵了"或"帮我做个安全体检"，Claude 会自己按流程调这些脚本，还会把 `ps`、日志、外连 IP 那些原始输出翻译成人话、排好优先级。不用 Claude Code 的话，直接跑脚本也一样。

## 特征库更新

特征库主要靠人工维护。最值钱的进程名、文件路径、家族标志物只能靠人读威胁报告补，自动源里没有。

`update-feed.sh` 是个可选的半自动补充：从 [abuse.ch ThreatFox](https://threatfox.abuse.ch/) 拉近期被标为 Linux 家族的恶意域名，过四道关卡——合法域名黑名单先滤一遍（免得把 GitHub、网盘这些也标成木马）、归一化到主域名、去重、再跑误伤测试，最后出一份待确认清单，人看过了才合并。

```bash
export THREATFOX_KEY=你的key    # abuse.ch 免费注册
bash update-feed.sh             # 拉取过滤，出待审清单，不改库
bash update-feed.sh --merge     # 看过没问题，合并进库
```

没做成全自动是有意的：域名类情报产出本来就少，而且自动入库会绕过人工这道闸。生产服务器保持不联网，特征库在维护端合好了随脚本一起分发。

## 几句丑话

这工具是给你自己的、或者拿到明确授权的机器用的，别拿去动没授权的系统。应急模式默认会杀进程删文件，是破坏性的，虽然防误伤下了不少功夫，第一次用还是建议先 `--dry-run` 看一眼。要是确认中了内核级 rootkit，别清了，重装——没有哪个清理工具能保证清干净，也没法验证清干净了。用出问题作者不背锅。
