# WorkLikeRico 落地任务书

2026-09-09 更新：按用户补充收紧首期范围，使用现有 GPT / MiMo 订阅，简单需求直接解决。

## 交付目标

一个本地 Hermes 助手，用你现有的能力处理和跟进工作；一个 GitHub 项目 `worklikerico` 维护自建 skills 与插件；一份短工作协议说明怎样执行、验收和提醒。

直接使用 Hermes 原生消息入口、cron 和任务看板。GPT / MiMo 走原生支持的订阅入口，不额外开发代理、调度器、任务数据库或控制台。

最新优先级（2026-09-09）：先完成基础环境，深入核对工作习惯要求并落实到插件。日常监测已明确暂停，不自动创建、恢复或预设提醒频率。已完成的历史分析和规则属于第一版，不能把资产归并说成全部插件已按工作方式重制验收。

本阶段按[工作习惯研究与插件落实任务书](habits-plugin-rebuild.md)推进，企业微信业务证据与 Codex 代表任务分别只读取样，再统一核对规则和实现缺口。

## 第一件实际工作怎么验收

从获准消息或本地资料得到一项明确任务 → 调用现有能力执行 → 检查实际结果 → 给出简短交付或具体阻塞。重复信息不重复执行，未变化不刷屏，取消后停止。

已完成一次本地资料任务：原生 gateway 自动领取，读取实施计划与仓库状态，生成下一步摘要；输入哈希保持一致。首次内容验收发现重复确认和虚构整理工作，修正默认角色后同一任务复验通过。该任务使用接入 MiMo 前的计划快照，不能用其中的待接入描述判断当前订阅状态。

普通文件任务只做内容检查和源文件保留。涉及实际发布、付费、生产或重要数据时，才增加与影响相称的授权和独立验证。

## 接入前提

- GPT和MiMo订阅分别使用自身支持的认证方式；不把现有Codex登录误写成Hermes已登录。
- Telegram机器人只能获取机器人可见信息；个人已有历史需要账号客户端或导出方式。
- 企业微信客户端已登录；机器人/应用不能默认读取个人全部历史，会话存档取决于企业权限。现有Rico需核对API长连接、Bot ID/Secret与可使用成员；该模式不需要本机公网IPv4或回调域名。
- 私人记录、任务数据库和凭据留在本机；GitHub只保存代码、脱敏规则与样例。

详细调查保留在本机，不要求日常助手每次读取。后续状态见 [status.md](status.md)，Hermes操作见 [安装说明](../hermes/INSTALL.md)。
