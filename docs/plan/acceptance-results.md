失联恢复补证使用固定 Hermes 0.21.1 的原生 Kanban 接口，数据库位于全新隔离目录。确认测试 PID 存活并持有领取记录后终止该 PID；死亡检测使用零宽限测试设置。另一任务等待真实两秒租约自然过期，再显式回收并启动替代进程，未改时钟或数据库到期时间。控制器模拟旧运行编号的迟到提交，原生条件更新返回拒绝；任务仍保留新 PID、新 claim 和空结果，只有新运行编号提交成功。七项断言通过，主线程另核对状态证据和进程退出。该试验不覆盖外部操作幂等、模型持续执行、默认宽限时长或后台调度触发；不因此恢复日常监测。

随后单独补测自动触发：在隔离环境运行原生 `_kanban_dispatcher_watcher` 循环，保留原生 tick、数据库、领取、死亡检测和重派逻辑，只将模型 CLI 的 spawn 工作载荷替换为受控睡眠进程。循环经过原有五秒初始等待自动派发，测试终止首个 PID 后，后续循环自行记录 `crashed` 并派发不同 PID 和 run；没有手动调用 tick、detect 或 reclaim。试验采用一秒间隔、零死亡检测宽限，自动拆解关闭，singleton lock 位于隔离目录。主线程核对事件、run、PID、循环退出及锁释放。替代任务的完成由控制器提交，仅为停止测试，不算真实模型完成业务；完整平台启动和真实工作接续仍是未验证边界。

首个专项技能 `xmind` 已完成 Hermes 原生发现、一次真实 CLI 创建与回读，输入哈希保持不变。自然语言追加验证证明自主选技与创建可行，但模型在回读被拦截后错误声称已检查；对应脚本和调用接口已做确定性修复与独立审查，但未再跑模型；不能用代码检查或独立终态校验冒充自然语言闭环通过。此样例也不证明机器人附件交付或所有 XMind 功能已经验收。尚未完成的渠道授权行为测试曾被自动安全检查拒绝，本轮仅保留只读配置核对，未将其记作通过。
