## 插件分工

- **核心 Skill**：工作判断与完成口径，只维护一份。插件不各自复制整套规则。
- **协作插件**：委派、交接、失败和取消状态。已有角色足以承担挑战或独立复核，不因此新建角色系统。Codex 与 Claude 启用机制分别验收。
- **记忆插件**：保存事实、任务和经验，并支持按范围召回。Codex 当前缓存的真实 MCP 已通过临时数据库中的存取、取消终态、范围隔离与跨进程持久化；无需重建数据库或调度器。Claude 与上层自动调用仍分别验收。
- **验收插件**：设计和验证入口。本轮确认独立安装缺少三项自身要求的 Skill，已在 Codex 版 2.1.0-codex.2 补齐原有技能；不依赖全局恰好已安装，也没有新增状态机。
- **专项 Skill**：将规则应用到具体文件、云资源或服务。未运行专项任务的技能不宣称已通过真实业务验收。

## 当前改动边界

本轮核心修改在规则表述层：补足业务前提、用户定稿与偏好语境，并纠正示例中的重复授权倾向。企业微信补证后，进一步落实巡检判断、批量剩余范围和已约定期限，并同步 Hermes SOUL。复测纠正了“把用户主动暂停当作待恢复故障”的行为。指定群继续补充供给约束、整改收尾和计划中断沟通；复用原有规则与示例，不新增角色或检查系统。未新增工具权限、模型提供商、数据库或定时任务。

Skill 格式校验只能证明结构可用。真实模型试验应检查实际输入是否保留、输出是否正确、未知是否被捏造和是否产生多余副作用；每次结果只覆盖被执行的场景。完整任务书见 [habits-plugin-rebuild.md](habits-plugin-rebuild.md)。

## 本轮行为验证

使用当前已安装的核心 Skill 入口，由一个未读取研究结论的 GPT-5.6-sol 独立执行者处理合成业务表格与用户定稿。实际产物由主线程另行读取，并与隐藏的输入哈希和预期差异比较：

- 两份源文件内容未变。
- 唯一可确定的算术错误得到修正；缺汇率、缺原始材料均保留未知。
- 用户定稿与内部使用边界完整保留。
- 仅输出指定的 Markdown 和 CSV，无额外交付格式。

上述断言全部通过。此结果只验证该安装入口下的一次业务处理行为，不证明企业微信业务理解、六包组合、跨轮接管或执行中取消已经完成验收。

企业微信补证后的 Hermes 原生单轮测试使用合成的批量升级与负载材料。首轮能识别未验证对象、持续异常和未获批准的规则变更，但错误建议恢复用户已暂停监测，判为失败。明确暂停与故障的区别后，同一输入复测通过；同步最终核心入口后又通过一次版本确认。结果仍指出真实缺口，同时明确恢复监测不属于当前待办或验收前提。持久会话记录确认三轮各 1 次 GPT 订阅调用、0 次工具调用，没有外发消息或创建定时任务。这只验证一个材料分析场景，不替代真实基础设施、持续运行或取消竞态测试。

验收插件另通过源码及当前安装缓存各 4 项包契约与 hook 正负样例测试；全新隔离目录的官方 CLI 安装实际生成六项 Skill，三个补入内容与既有统一技能一致。本地安装登记已更新且启用 2.1.0-codex.2，配置文件未改。当前长会话的工具目录可能仍来自旧快照，旧版本缓存保留供已打开会话使用；新会话的完整协作行为仍需按任务书验收。

Codex Memory Pro 2.0.0 使用真实 stdio MCP、现有嵌入服务和合成数据进行隔离验收。独立目录初始记录为零；事实、任务和教训均通过工具写入。关闭首进程后，以不同 PID、相同临时数据库重启，事实和教训可召回、取消任务仍保留且不出现在 open 列表、不同 scope/project 的记录保持分离。主线程另行核对返回内容与进程退出，临时数据库已清理，真实记忆库未改。当前接口在同名终态任务后再次创建会产生新任务，上层仍需防止晚到调用；该测试不证明取消竞态保护、Claude 入口或自动跨会话召回已经通过。


指定群补证后的供给与整改场景：两次 GPT 原生调用均因连接错误未取得可验收回答，不能计为通过。改用已配置的 MiMo 后，模型识别容量、验收与通知权限，但额外要求用户决定未选定的预售或采购方案，判为行为不通过；随后在核心与 SOUL 中明确“候选扩展方案不自动成为用户必须决定的阻断”。该场景只分析合成材料，不执行运维或外发。

同一输入的 MiMo 复测通过：保留真实供给限制和验收缺口，仅提出权限内的通知草稿，不再要求用户决定未选定方案，也不恢复暂停监测。主线程另查持久会话记录：四轮工具调用均为零，两个 MiMo 会话各记录一次 API 调用；GPT 失败会话计数为零不代表可以推断未消耗额度。这里只验收该材料分析场景，GPT 当前场景、持续执行和跨轮取消仍未由此证明。
