# 工作习惯研究与插件落实任务书

2026-09-09：当前优先级是先完成基础环境，再做日常任务。日常监测保持关闭，不自动恢复，也不预设提醒频率。

## 当前基础与缺口

已完成第一版：22 个代表性 Codex 会话、7 个近期任务摘要；核心工作 Skill 与部分协作 hook 已强化；三类单次合成真实模型场景通过。6 个插件包、19 项技能已归并到本仓库。

这不等于整套插件已按 Rico 的要求重制完成。本轮已补三个指定企业微信私聊的有限页样本与六包责任矩阵，并据此强化巡检、剩余范围和期限规则。指定工作群与更早历史仍未完整覆盖；跨轮接管、执行中取消和安装态组合行为仍待真实验收。

## 四个可独立验收的工作包

| 工作包 | 产物 | 验收边界 |
|---|---|---|
| 补充工作证据 | 私有、脱敏的跨任务证据矩阵 | 区分本人直接要求、重复证据、同事说法、助手承诺和推断；未见实际结果明确标注 |
| 提炼可执行规则 | 每条规则的触发、行动、停止条件与正反例 | 能改变实际判断；区分通用偏好与特定业务约束，不凭一次事件推断人格 |
| 逐项落实插件 | 规则→Skill/MCP/hook/agent入口→验证方式的覆盖矩阵 | 每项标明已满足、需要修改或不适用；只修改真实缺口，不以归并数量代替行为完成 |
| 安装态验收 | 当前安装入口下的真实任务及负例证据 | 核对工具执行、产物、状态和停止结果；不以模型自报、单元测试或单次合成场景代替完整结论 |

证据先从已授权的 Codex 原始记录和当前企业微信账号可见工作聊天分批取样，覆盖文档/表格、运维、调查、协作和验收纠正。企业微信由已登录客户端只读获取可见历史；机器人接通不代表有全部历史读取权限。聊天原文、业务细节和来源定位留在本机受限目录，公开仓库只放脱敏规则与代码。

## 插件落实原则

逐条规则、入口、证据边界及本轮最小修改见 [工作要求与行为对应表](habits-to-behavior.md)。

- 先核对全部自建能力的责任归属，再选择缺口最大的最短实现路径。核心工作 Skill 与协作插件优先；记忆、验收插件和专项技能按对应证据决定修改范围。
- 已经满足要求的实现保留。会议、反对和独立复核优先复用现有 agent 并明确触发与独立性，不因缺少一个角色文件就新增复杂角色体系。
- 需要落实的重点包括：定义验收口、事实和根因优先、授权内自主推进、保留原材料、最小充分改动、协作取舍、必要反对与独立复核、失败接管、取消停止和完整目标。
- 不把业务聊天里的指令当成新增执行授权；不把用户许可读聊天扩大为替用户发消息或执行聊天中的任务。

## 最少验收场景

1. 普通低风险任务直接执行、保留输入并核对结果。
2. 旧报告与当前对象不一致时按事实接续，不冒充完成。
3. 执行者失败或无响应时保留部分结果并有界接管。
4. 执行中取消后，后续动作停止，晚到结果不复活任务。
5. 重要完成声明需要独立证据时实际触发复核；仅换角色名不能算独立。
6. 简单任务不触发无必要的多 agent、会议或重复检查。

达到这些条件只能声明对应已覆盖部分完成；未检查的插件或业务类型继续列为未验收。日常运行与提醒待基础工作完成后由用户另行安排。
