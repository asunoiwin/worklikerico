# 独立验收输入

这份材料描述原始需求与预期，不包含实现者的测试结论。独立复核者先独立设计案例，不读取上一轮报告，然后记录执行环境、实际结果与证据。

## 用户要求

- 单一 GitHub 源码项目维护所有自建记忆、协作、工作方法和云运维等插件/skills，保留本地修改与必要来源。
- 按历史证据提炼工作方式，强化项目验收和主动跟进；不只增加一份抽象宣言。
- 本地部署 Hermes，桥接 Telegram 和企业微信，持续处理日常工作并推进新工作，复用已存在的能力。
- 先调查真实状态与可达边界，再按可拆分任务书落地；完成必须有对应证据。

## 第一轮应得到的证据

| 面向 | 必须看到 | 不应出现 |
|---|---|---|
| 发布包 | 可追溯资产目录、许可证、相对路径和可安装入口 | 私人聊天/任务正文、凭据、运行DB、无来源的第三方复制 |
| 能力归并 | 每项自建资产有目标或清楚的未纳入理由，源改动保留 | 仅保存patch就声称所有功能合并 |
| 安装者 | 临时环境安装、重复执行、冲突与回滚可验证 | 覆盖现有用户文件、依赖原机器绝对路径才能运行 |
| 普通工作 | 已授权可逆工作继续，保留源文件，验证实际产物 | 每步请示或套用与任务无关的生产流程 |
| 高影响工作 | 授权范围和当前证据明确，独立复核可追溯 | 同一执行者换个角色名就自证通过 |
| 消息输入 | 获准来源、重复处理规则、数据/指令边界明确 | 收件内容可以直接提升权限或下发任意命令 |
| 任务推进 | 明确状态、阻塞原因、下一动作、暂停与恢复 | 失败永久running、旧结果复活取消任务、无变化刷屏 |
| Hermes | 独立配置与版本固定，CLI/持久化/执行分别记录 | 原生done自动被宣称用户验收通过 |
| 实网渠道 | 真实收件与范围证明 | 未登录也声称已读历史、模拟当平台成功 |

至少分别检查：正常路径、重复/失败/取消负例、未授权来源或缺证据路径。若模块无GUI，用进程/文件/数据库/结构化输出替代HTTP/DOM，仍分别验证调用是否成功、产物是否存在、业务值是否正确。

## 输出约定

- PASS、FAIL、UNCLEAR按子项报告；未测必须给具体缺条件。
- 给最短复现步骤、对应文件和行号、实际业务结果；长日志留在本地证据目录。
- 不把代码审阅当真实运行，不把确定性文档校验当模型行为评估。
- 发现失败交回对应owner修复；保留有价值结果，不重读全部旧记录。
